fix: coerce pr title types to the repo's allowed list

## Description

**Key Changes:**

- Added a deterministic backstop in the output filter that rewrites a PR title's conventional-commit type to one the repo's title check accepts, since prompting alone still yields `test:` for test-only diffs
- Wired a `PR_ALLOWED_TYPES` environment variable through the PR filter wrapper so the allowed list reaches the filter as repeated `--allowed-type` flags
- Taught the PR agent prompt to treat an `ALLOWED PR TITLE TYPES` input block as the complete set of permitted types

**Added:**

- Title type coercion - `coerce_title_type` in `scripts/filter.py` matches the first line against a conventional-commit pattern and swaps only the type word, preserving the scope, the `!` marker, and the title wording. A `_TYPE_FALLBACKS` table maps housekeeping types (`test`, `ci`, `build`, `style`, `refactor`, `perf`) to `chore` and `revert` to `fix`, falling back to `chore` or the first allowed type when no mapped candidate is permitted. Exposed through a new repeatable `--allowed-type` CLI argument and an `allowed_types` parameter on `filter_text`, applied as the final filter step
- Restricted-types guidance - a "WHEN THE REPO RESTRICTS THE TYPES" section in `pr/system.md` explaining that the allowed block is exhaustive and that test-only or tooling changes become `chore` when `test` or `ci` are not listed
- Coercion test coverage - a `TestCoerceTitleType` class in `tests/test_filter.py` covering allowed types left untouched, fallback mappings, scope and bang preservation, body lines left unmodified, the no-`chore` fallback, empty allowed lists, untyped titles, and the `filter_text` integration with and without an allowed list

**Changed:**

- PR filter wrapper - `pr/filter.sh` now reads `PR_ALLOWED_TYPES` line by line and appends an `--allowed-type` argument for each non-empty entry before invoking the filter
- Title type hard rule - the rule on starting the title with a type now permits choosing from the `ALLOWED PR TITLE TYPES` block when one is present
