```markdown
fix: coerce pr title types to the repo's allowed list

**Key Changes:**

- Added a deterministic backstop in the output filter that rewrites a PR title's conventional-commit type when it falls outside the repo's allowed list, since prompting alone still yields `test:` for test-only diffs
- Wired a `PR_ALLOWED_TYPES` environment variable through the PR filter wrapper so each listed type reaches the filter as a repeatable flag
- Taught the PR prompt that an `ALLOWED PR TITLE TYPES` block in the input is the complete set of permitted types

**Added:**

- Title type coercion - New `coerce_title_type` function and `_TYPE_FALLBACKS` table in `scripts/filter.py` map disallowed types to the nearest permitted one (housekeeping types such as `test`, `ci`, `build`, `style`, and `refactor` to `chore` then `dev`; `perf` to `chore` then `fix`; `revert` to `fix` then `chore`), falling back to `chore` or the first allowed type when no mapping applies. Only the type word changes: scope, `!`, title wording, and the body are preserved, and untyped titles are left alone
- `--allowed-type` CLI flag - Repeatable argument that feeds a new `allowed_types` parameter on `filter_text`, with the coercion applied as the final filter step and skipped entirely when no list is given
- Restricted-types prompt guidance - New "WHEN THE REPO RESTRICTS THE TYPES" section in `pr/system.md` explaining that CI rejects any type outside the block and that test-only or tooling changes become `chore` when `test` or `ci` are not offered
- Coercion test coverage - `TestCoerceTitleType` in `tests/test_filter.py` covers allowed types passing through, the `chore` and `fix` fallbacks, scope and bang preservation, untouched body lines, the first-allowed fallback when `chore` is absent, no-op behavior for empty lists and untyped titles, and integration through `filter_text`

**Changed:**

- PR filter wrapper - `pr/filter.sh` now reads `PR_ALLOWED_TYPES` line by line and appends an `--allowed-type` argument for each non-empty entry before invoking the filter script
- Title type hard rule - Rule 5 of the PR prompt now permits choosing the type from the `ALLOWED PR TITLE TYPES` block when one is present, rather than only from the standard list
```
